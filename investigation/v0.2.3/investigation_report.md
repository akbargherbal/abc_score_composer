**Scope.** Two sessions on the same Arabic Suno-style prompt: P (`كتابة سكور ABC لقصيدة عربية`, 06:51–07:10 UTC) and S (`كتابة سكور ABC لأغنية عربية`, 06:36–07:40 UTC). One deliverable: this report. No skill edits, no fixes, no listening to audio.

**Evidence tags used below**

- **[T]** transcript: session + message index (the zip contains full tool calls and results; thinking text is redacted, only short summaries remain).
- **[R]** reproduced: I replayed the agents' exact commands in a copy of the repo (`/tmp/opencode/skill_src`, v0.2.3, commit `4081fc1`) and got byte-identical `.abc` files (`replay_P.log`, `replay_S.log`).
- **[O]** observed on the owner's real consumer: `abc2audio` repo commit `535c49a` (`abc2audio.py`), which calls `abcjs` 6.7.2 (`js/abc_to_midi.js`). I ran the abcjs MIDI stage (the stage that emits the warnings and the chord track); I did not render WAV because this container has no FluidSynth/SoundFont. That does not affect the warning or track findings.
- **[A]** agent testimony: a hypothesis, not proof.

**Important correction to the working hypothesis.** Before `abc2audio` was available I suspected the "drummer" was `abc2midi`'s default `gchord` accompaniment. That is **refuted**: the owner's pipeline is `abc2audio → abcjs → MIDI`, not `abc2midi`. `abc2midi` is only the skill's validator (`SKILL.md:60,77`). The chord track the owner hears is generated by **abcjs** from the ABC's chord symbols, and it is analysed as such in W5-h.

## 1. Executive summary (10 lines)

1. Both sessions are the same task on the same prompt; intake fixes **116 bars, 7 sections, 93 BPM, Dm, a Dm–Gm–Bb–A loop, and 4/3/3/4 syllable splits** before the model writes a note. [T P/S msg0–1; R]
2. The model then wrote the whole first fill **in one pass from templates**, not line by line; both agents admit it, and the fills are Python pattern generators. [A P msg7, S msg7/11; R `gen_fill.py`] — **high confidence**.
3. The quality gate is **structural only**; CRAFT is "advisory, do not chase," and the loop allows one musical patch, so both agents stopped at the first green build. [T S msg11; `SKILL.md:22-24,74-75,94`] — **high**.
4. The skeleton's 4/3/3/4 split puts **four syllables in the breath bar**, leaving 2–2.5 beats, while the prosody rule simultaneously demands `r:1.5`/`r:2` there. [R intake; `intake_lyrics.py:371-378`; `vocal_craft.md:56-60`] — **high**.
5. The CRAFT register target (**12 st between verse phrase medians**) contradicts its own advice ("lift the ajuz 4–7 st") and was never reached; every patch still flagged. [R P/S logs; `craft_thresholds.json`; `vocal_craft.md:80-82,135`] — **high**.
6. The near-identical sound is **not copied melody**: shared 8-gram containment is **0.000**, but P1/P2/S1 share a **bit-identical 928-note abcjs chord track**, identical cadence pitch classes on **11–12/12** verse lines, and identical breath placement. [R similarity; O abcjs] — **high**.
7. The "drummer" is that chord track: abcjs generates **8 bass/chord events per bar** from the chord symbols, program 0 (piano), **no channel 10**; the agent's "renderer reads the style prompt" answer is refuted. [O `abc2audio.py:123-141`; README:82-84; MIDI parse] — **high**.
8. The validator/consumer mismatch is real: the skill validates **abc2midi**, the owner renders with **abc2audio/abcjs**; abcjs warns on durations **5, 9, 10, 11, 13 units**, abc2midi accepts them. [O `abc_parse_music.js:563-565`; R `t.abc`; P/S warnings] — **high**.
9. Targets are **self-graded**: `melisma 1.2` has no corpus basis (the corpus has no lyrics), `vocal_span 20` is a p90 cap, and S v2 raised them to 22/5 without penalty. [`blueprint_schema.md:30`; `corpus.md:3,37`; R `S/skeleton2.json`] — **medium-high**.
10. Cost: both sessions land near/above the **10× budget** (R≈12.7 P, 14.4 S on v1; 10.0/13.0 on v2), and the only owner-approved output (S v2) came from the **expensive rewrite** (R≈8.0 for that phase), not the cheap first-pass compose (R≈2.8). [R cost table] — **medium** (thinking estimated).

**Method.** I used the repo's own tokenizer (`scripts/novelty_check.py`, `N = 8`, interval/rhythm classes) on the Vocal voice of the four delivered scores and `assets/example_song.abc`, plus the MIDI produced by the owner's real renderer (`abc2audio → abcjs`). Files: P1 `P_v1.abc`, P2 `P_v2.abc`, S1 `song.abc`, S2 `song2.abc`.

**Which version is P1/S1.** P1 is the **post-duration-fix** 480-note delivery; the 27-warning render was the 453-note first delivery (`replay_P.log:537-555`). S1 is the **post-rest-patch** 455-note delivery; the 14-warning render was the same 455-note score before the rest patch (`replay_S.log:487-520`). ### 4.2 The layers that actually make them sound alike

| Layer | P1 | P2 | S1 | S2 | Source |
|---|---|---|---|---|---|
| Bars / sections / tempo / key | 116 / 7 / 93 / Dm | same | same | same | **intake** (100%) |
| Chord symbols | Dm–Gm–Bb–A loop | same | same | 7 chords (Dm, C, Gm, Bb, A, D, Eb) | intake (P1/P2/S1); model (S2) |
| abcjs chord track | 928 notes | **928, bit-identical to P1** | **928, bit-identical to P1** | 928, different pitches | **abcjs from chords** |
| Verse line-final pitch classes | G,A,E,A,G,A,E,A,G,A,G,A | same | G,A,E,A,G,A,G,A,G,A,G,A | same as P1 | **instruction** (cadence rule) |
| Breath rests | 1.5 / 2.0 every line | same | same | same | **instruction/compiler** |
| Distinct verse bar-rhythm patterns | 14/48 | 17/48 | **6/48** | **28/48** | model |
| Distinct verse contour shapes | 9/12 | 12/12 | **7/12** | 12/12 | model |
| Mean pairwise contour 3-gram overlap | 0.760 | 0.606 | **0.857** | 0.682 | model |

**Cadence identity.** Across all pairs, the verse line-final pitch classes agree on **11–12 of 12** lines; the chorus agrees on 3–6 of 6 (it converges to G,A,G,A,G,D after the rewrites). This is not melodic copying; it is the cadence rule (`sadr` ends on 2/4/5, `ajuz` on 5/1) applied to the same chord loop, so every phrase lands on the same small set of pitches.

**The accompaniment is the loudest shared layer.** Running the owner's actual pipeline (`node js/abc_to_midi.js`) on P1, P2, S1, S2 produces a third MIDI track (channel 3) of **928 notes** = 116 bars × 8 events, program 0 (piano), range 28–62. Its pitch sequence is **bit-identical for P1, P2 and S1**; only S2 differs, because S2 changed the chords. That is a concrete, measurable "near-identical" component that no vocal-melody metric can see.

**Why `novelty_check` missed it.** `novelty_check.py` tokenizes only the voice with the most notes (`notes_from_parsed(parsed, None)`, `novelty_check.py:58-76`), i.e. the Vocal, and compares vocal interval/rhythm 8-grams against the corpus bank. It ignores the chord track, the Ins voice, the form, and the other session. Its `NOVELTY closest=none containment=0.000` (S msg1) therefore correctly says "not a corpus copy" while being blind to the identical backing and form. It is the wrong instrument for the owner's complaint.

## 6. Defect list (W5)

Severity: **H** = quality or correctness blocker; **M** = cost/robustness; **L** = cosmetic.

### W5-a. Representable durations (H; correctness + cost)

**Reproduction (owner's real consumer).**

```bash
cd /tmp/opencode/abc2audio
node js/abc_to_midi.js t.abc t.mid
# {"warnings":["Music Line:8:27: Duration not representable: F10: ..."]}
abc2midi t.abc -o t.mid   # exit 0, no warning
```

**Observed.** abcjs's duration whitelist (`node_modules/abcjs/src/parse/abc_parse_settings.js:114-123`) contains note values `0.5, 0.75, 0.875, 0.9375, 0.96875, 0.984375, 0.25, 0.375, 0.4375, 0.46875, 0.484375, 0.4921875, 0.125, 0.1875, 0.21875, 0.234375, 0.2421875, 0.24609375, 0.0625, …`. For durations **less than a whole note**, a value not in this list triggers `warn("Duration not representable: …")` (`abc_parse_music.js:559-566`). At `L:1/16`, that means units **1, 2, 3, 4, 6, 7, 8, 12, 14, 15** are accepted, while **5, 9, 10, 11, 13** are rejected. Values **≥16 units (a whole note or longer) are not tested at all** ("whole note durations have some tricky rules"), which is why `D17…` produced no warning. The compiler's only check is grid divisibility (`compile_abc.py:814-818`), and it renders any integer unit as a bare `N` (`compile_abc.py:846-856`). So the first compile emitted `F10/G10/z10` (2.5 beats) and abcjs warned 27 times in P and 14 in S.

**Expected.** The compiler should either split non-representable values into tied representable ones or reject them with a `grid`/`duration` error before release. **Who it affects:** correctness (the owner sees warnings), cost (a whole debug round in both sessions).

### W5-b. Syllable-to-bar split vs the breath (H; quality)

`bar_syllable_ranges` (`intake_lyrics.py:371-378`) balances the remainder to both ends, producing **4/3/3/4** for a 14-syllable line, 4/4/3/4 for 15, 4/4/4/4 for 16. The last bar therefore always has **4 syllables**. The prosody rule puts `r:1.5` (sadr) or `r:2` (ajuz) in that bar (`vocal_craft.md:56-60`; `SKILL.md:102`), leaving **2–2.5 beats for 4 syllables**. P1 verse L1 last bar is literally `F2G2F2G4z6` (`P/P_v1.abc:18`) = 2.5 beats of singing for 4 syllables, then a 1.5-beat (`z6`) breath; P2's L1 bar is the Blueprint `b3:.5 2:.5 b3:.5 4:1` plus `r:1.5`. S2 fixed this by re-splitting to **4/4/4/2** (S msg9); the owner preferred the result. **Expected:** the skeleton should reserve the last bar for 2–3 syllables, or the breath should be counted in the split. **Who it affects:** quality (fast, unheld line endings); cost (the rewrite).

### W5-c. Fixed chord loop and its audible effect (H; quality + near-identical)

`chord_loop()` (`intake_lyrics.py:355-365`) returns `i–iv–VI–V` for minor keys, i.e. **Dm–Gm–Bb–A** in Dm, and `build_skeleton` assigns it to **every section** (`intake_lyrics.py:430-440`). P1, P2 and S1 keep this loop for all 116 bars; the chorus is Hijaz (b2/3) over Nahawand/Dm–Gm–Bb–A chords (S msg7 says exactly this). P1/P2/S1 end on **A** (unresolved); S2 is the only one that writes its own chords and ends on **Dm**. The abcjs chord track makes the loop audible: 928 notes, identical in P1/P2/S1 (W5-h). **Expected:** a section-varying progression, a tonic ending, and a chorus that supports the Hijaz notes. **Who it affects:** quality and the near-identical perception.

### W5-d. `[End]` section typing (M; cost/correctness)

`normalize_kind` defaults unknown names to `"verse"` (`intake_lyrics.py:237-247`). `[End]` is not in `KIND_MAP`, so intake prints `[End] key=end kind=verse lines=0 … bars~4` (S msg1 output). The compiler then rejects it: `bad_verse_bars: verse has 4 bars; write whole bayts… section "end"` (P/S msg1). Both agents hand-edited `kind='outro'` in the skeleton (P `01_14`; S `01_14`). **Expected:** `[End]`/`[Coda]` should map to `outro`, or a 4-bar lyric-less section should not be checked as a verse. **Who it affects:** cost (a manual edit every run), correctness.

### W5-e. Intro with lyrics (M; expressiveness)

The prompt's `[Intro]` has two lyric lines. The compiler warns `lyrics_unused` if any intake line is not referenced (`compile_abc.py:976-996`), and the release criterion says "no intake line is unused" (`SKILL.md:93`). So the intro's lines must be sung; both agents filled the intro with the same words as verse 1. An instrumental intro would require knowingly leaving lines unused (it is a **warning**, not an error — the code appends to `warnings`, not `errors`), which the agent read as forbidden. S msg11 item 6 states the constraint. **Expected:** either allow an instrumental intro with a documented `instrumental: true` section, or state that the warning is advisory. **Who it affects:** expressiveness (no instrumental intro).

### W5-f. Syllable tokens and prosody weights (M; quality)

`intake.json` line records have `syllables`, `count`, `role`, `bayt`, `est_bars`, but **no weight/long-short field** (S `intake.json`). The tokenizer splits long vowels into separate tokens: `يُعَارِضُ` → `يُ`, `عَ`, `ارِ`, `ضُ`; `الرِّيحَ` → `الرِّ`, `يحَ`. The long vowel's consonant is in the previous token (`عَ`), and the vowel letter starts the next (`ارِ`). S2's `weight()` only checks `'ا'` (`compose.py`), so it catches `ارِ` but misses long **و/ي** (`يحَ`). The larger dropped signal is metrical: the prompt is classical metrical verse, but intake exposes only a syllable list and count, no bahr/taf'il and no strong/weak positions. Even a perfect long/short weight would not tell the model which syllable is metrically strong. The data is recoverable with a better heuristic, so "no usable prosody" (S msg11 item 4) is too strong; "no explicit weights, and the tokenizer obscures CV structure" is accurate. **Expected:** expose `weight`/`long` per syllable, preserve CV units, and (if possible) a metrical parse. **Who it affects:** quality (text-setting).

### W5-g. Style-prompt coverage (H; quality vs prompt)

The prompt asks for: classical Arabic, melismatic, **microtonal ornaments**, belting, tarab, Khaliji, emotive delivery, **symphonic metal**, powerful operatic, **rhythm guitar**, **electric oud**, epic, clear enunciation, vocal-forward mix, crisp consonants, audiophile, call and response, **backing vocals**, **rich layered vocal harmonies**, **massive choir**, Maqam Nahawand, Natural Minor, mood. The skill can express: two monophonic voices (`Vocal`, `Ins`), key/meter/tempo, chord symbols, 12-TET scale degrees, melisma groups, and a maqam label for the report. It cannot express: quarter tones (`maqam.md:55`), dynamics/articulation/belting, distortion, drums, choir, backing vocals, mixing, or enunciation. Both agents collapsed the instruments into one Ins line (P: root–fifth patterns; S: arpeggios); neither attempted choir/backing/drums. S msg7: "It is a mechanical arpeggio or root-and-fifth pattern… far from an epic symphonic-metal or electric-oud texture." **Expected:** at least `%%MIDI program`/`chordprog` per voice (abcjs honors them; tested), a percussion/choir voice or a documented "cannot express" list. **Who it affects:** quality (the output cannot match the prompt).

### W5-h. The "drummer" (H; diagnosis)

**Reproduction.**

```bash
cd /tmp/opencode/abc2audio
node js/abc_to_midi.js /tmp/opencode/work/art/S/song.abc out.mid
python3 /tmp/opencode/work/midiparse.py out.mid
# TRACK 1 'Vocal Melody' ch1 program 0
# TRACK 2 'Ins Melody'   ch2 program 0
# TRACK 3 (no name)      ch3 program 0, 928 notes, range 28-62
```

**Observed.** `abc2audio` is a thin CLI: it passes only the ABC path and CLI options to `abcjs` (`abc2audio.py:123-141`); `abc_to_midi.js` calls `abcjs.synth.getMidiFile(tune, params)`; the README says "**Chord symbols produce accompaniment.** abcjs generates a chord track from annotations like `"Cm7"`" and "unless the ABC sets `%%MIDI program`, all voices use piano (program 0)" (`README:82-84`). The result is a **third track on channel 3, program 0 (piano), 928 notes = 116 bars × 8 events**: bass on beats 1 and 3, triad on beats 2 and 4 (first bar: 38; 50/53/57; 33; 50/53/57). There is **no channel 10 and no percussion program**. The pitch sequence is **bit-identical in P1, P2 and S1** (same Dm–Gm–Bb–A loop); S2 differs because its chords differ. This is the only non-vocal, non-Ins content the owner hears, and it is rhythmically independent of the vocal.

**Refutation of S msg3.** The agent said the drummer is "the audio renderer's own interpretation of your style prompt." `abc2audio` never sees the style prompt: its input is the `.abc` file plus CLI flags (`abc2audio.py:123-141,212-233`). The chord track is derived from the ABC's chord symbols, not from "symphonic metal/epic." The agent's first sentence ("the score I wrote has no drum part") is true; the causal explanation is false.

**What the owner heard.** Observed: a rigid piano oom-pah (root/chord/root/chord) under a free vocal, identical across sessions. Inferred: that is what "the drummer seems to be playing his own idea instead of interacting with the singer" describes. Inconclusive: whether the owner literally heard a percussion timbre or used "drummer" as a metaphor for the accompaniment; the MIDI has no percussion. **Expected:** either suppress the chord track (`--no-chords`, or omit chord symbols) or write a progression that supports the vocal; do not blame the renderer's style prompt. Note: `%%MIDI gchordoff` is **ignored** by abcjs (tested; ch3 still 928 notes), so the skill cannot suppress the track from inside the ABC — only `--no-chords` or removing the chord symbols works. **Who it affects:** diagnosis, quality, trust.
